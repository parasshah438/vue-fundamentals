Core Concepts

What is CI/CD?

CI/CD is a set of automated practices that helps teams build, test, and deliver software reliably.

Continuous Integration

CI automatically builds and tests your code whenever changes are pushed to a shared repository.

Continuous Delivery / Deployment

CD prepares a successful build for release or automatically deploys it to staging or production.

Git

A version control system that tracks code changes.

GitHub

A platform for hosting Git repositories and collaborating with other developers.

CI/CD

An automated process for building, testing, and deploying software.

Why CI/CD?

Automate repetitive work and reduce mistakes

In a real company project, many developers may push changes every day. CI/CD automatically checks whether the complete application still works before it reaches users.

  • Install project dependencies automatically.
  • Run tests on every change.
  • Detect broken code early.
  • Prevent failed builds from being deployed.
  • Deploy consistently with fewer human errors.

GitHub Actions

A workflow file starts the automation

GitHub only runs Actions workflows that exist inside the .github/workflows/ directory.

If you do not create a workflow file such as .github/workflows/laravel.yml, GitHub Actions CI/CD will not run.

Your Laravel application will still work normally. You can still use Git commands and push your code to GitHub. However, no automatic testing, building, or deployment will happen.

.github/workflows/laravel.yml
name: Laravel CI

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - Checkout source
      - Setup PHP
      - Install Composer packages
      - Run Laravel tests
Laravel Example

A Laravel CI/CD pipeline

A Laravel pipeline normally validates the application before deploying it to staging or production.

Pipeline steps

  • Checkout source

    Download the latest code from the repository.

  • Set up PHP

    Prepare the PHP runtime and required extensions.

  • Install dependencies

    Install Composer and Node.js packages.

  • Run tests and quality checks

    Execute PHPUnit or Pest tests, linting, and code checks.

  • Build frontend assets

    Compile CSS and JavaScript using Vite.

  • Deploy application

    Deploy to staging or production after all checks pass.

Laravel commands
composer install
npm install
php artisan key:generate
php artisan test
php artisan migrate --pretend
npm run build
php artisan config:cache
php artisan route:cache
php artisan view:cache
Production database migrations should be handled carefully. Use backups, approvals, and a controlled deployment process before running php artisan migrate in production.

Real-World Example

CI/CD catches problems early

Without CI/CD

A developer adds the following code but forgets to create the required database column:

User::create($data);

The code is pushed directly to production and users see:

SQLSTATE: Unknown column 'phone'

With CI/CD

Automated tests run before deployment and detect the problem:

Running tests...

❌ User registration test failed
Deployment cancelled

The developer fixes the issue before users are affected.

Getting Started

Workflow filenames are your choice

GitHub only requires workflow files to be placed inside:

.github/workflows/

The filename itself is flexible. Choose a name that clearly describes the workflow.

Common workflow names

ci.yml
deploy.yml
test.yml
release.yml
security.yml
laravel.yml
react.yml
node.yml

Start small, automate gradually

Begin with automated tests. Add builds and deployment when your project grows and deployments become repetitive or risky.
