What is Artificial Intelligence?

Artificial Intelligence (AI) is the field of computer science that builds systems able to perform tasks that normally need human intelligence: understanding language, recognising images, making decisions, learning from data, planning, and creating new content. Modern AI is mostly software that learns patterns from data instead of following hand-written rules.

Perceive

See, hear and read: image recognition, speech-to-text, document understanding.

Reason

Solve problems, plan steps, write code, do maths, answer questions.

Create

Generate text, images, audio, video, music, 3D models and software.

Act

Use tools, call APIs, browse the web, control robots and complete multi-step tasks.

Rule-based Systems vs Learning-based Systems

There are two ways to make software "smart". In a rule-based system a human writes the logic. In a learning-based system the machine discovers the logic from examples.

Rule-based (symbolic AI)

Experts encode knowledge as IF ... THEN ... rules. The system follows them exactly. Examples: tax calculators, form validation, early expert systems (MYCIN, XCON), classic chess engines, simple FAQ bots.

Input + Rules → Output

Learning-based (ML / DL)

The model is trained on data and adjusts its own parameters. Examples: spam filters, recommendations, face recognition, speech recognition, ChatGPT-style assistants.

Data + Answers → Training → Model → Predictions

AspectRule-basedLearning-based
Where knowledge comes fromHuman experts write rulesPatterns learned from data
Data neededLittle or noneUsually a lot, and good quality
TransparencyHigh: every decision can be traced to a ruleLower: often a "black box" (needs explainability tools)
New or unseen casesFails unless a rule existsGeneralises to similar cases
MaintenanceRules multiply and conflict as the system growsRetrain with fresh data
Accuracy on fuzzy tasksPoor (images, speech, language)Excellent
PredictabilityDeterministic: same input, same outputProbabilistic: can be wrong with confidence
Best forClear regulations, calculations, safety-critical logicPerception, prediction, personalisation, language, generation
 
# Rule-based spam check: a human writes the rules
def is_spam(text):
    text = text.lower()
    return "free money" in text or "you are a winner" in text or text.count("!") > 5

print(is_spam("WIN free money now!!!"))   # True
print(is_spam("Cheap pills available"))   # False  (no rule for this, so it is missed)
# Learning-based spam check: the model learns from labelled emails
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.naive_bayes import MultinomialNB
from sklearn.pipeline import make_pipeline

emails = ["win free money now", "meeting at 10am", "cheap pills offer", "project report attached"]
labels = [1, 0, 1, 0]                     # 1 = spam, 0 = not spam

model = make_pipeline(TfidfVectorizer(), MultinomialNB())
model.fit(emails, labels)
print(model.predict(["free pills offer"]))   # [1]  (learned the pattern)

Hybrid is the norm: real products combine both. For example, an LLM chatbot (learning-based) is wrapped with business rules, input validation and guardrails (rule-based) so it stays safe and predictable.

Details: Trending use cases and AI by industry.

Benefits
  • Speed and scale: processes millions of records in seconds.
  • Automation: removes repetitive work such as data entry, sorting and first-level support.
  • Accuracy on narrow tasks: can match or beat humans at image reading, fraud spotting and forecasting.
  • 24/7 availability: consistent service without fatigue.
  • Personalisation: tailors content, learning and offers to each user.
  • Insight from data: finds patterns humans would miss.
  • Accessibility: captions, translation, voice interfaces and reading aids.
  • Creativity boost: drafts, prototypes and ideas in minutes.
Limitations
  • Needs data: poor or biased data gives poor or biased results.
  • No real understanding: it detects statistical patterns, not meaning or common sense.
  • Hallucinations: confident but wrong answers.
  • Brittle outside training data: can fail badly on unusual inputs.
  • Black-box decisions: hard to explain why a deep model decided something.
  • Cost and energy: training and serving big models needs expensive compute.
  • Security risks: prompt injection, adversarial examples, data leaks.
  • Knowledge cut-off: models do not know recent events unless connected to search or tools.
Common myths vs reality
MythReality
"AI thinks and understands like a human."Current AI predicts patterns from data. It has no consciousness, feelings or real-world experience.
"AI will take every job."AI automates tasks. Jobs change, some shrink, new ones appear. People who use AI well gain an advantage.
"AI is always objective and fair."AI inherits bias from data and design choices. It must be tested and monitored for fairness.
"If the AI sounds confident, it is correct."Fluent text is not proof. Always verify important facts.
"More data always means a better model."Quality, relevance and balance matter more than raw volume.
"AI keeps learning from every chat."Most deployed models are fixed. They only improve when the provider retrains them.
"AI means robots or ChatGPT."AI is mostly invisible software: search ranking, maps, spam filters, fraud checks, recommendations.
"You need a PhD in maths to use AI."Using AI tools and APIs needs little maths. Building models benefits from it, and you can learn gradually.
"AGI already exists."No system matches broad human ability today. Definitions and timelines are still debated.

How a Large Language Model (LLM) Works

An LLM is a Transformer neural network trained to predict the next token. Doing this billions of times on huge text corpora forces it to learn grammar, facts, reasoning patterns and code.

Inference: what happens when you send a prompt
1
Tokenize

Text is split into tokens (word pieces) and mapped to IDs.

2
Embed

Each token ID becomes a vector of numbers that captures meaning.

3
Attention layers

Transformer blocks let each token look at all others for context.

4
Probabilities

Model outputs a probability for every possible next token.

5
Sample

Pick a token (temperature, top-p), append it, repeat until done.

Training stages of a modern assistant
1
Pre-training

Learn language and world knowledge by predicting next tokens on trillions of tokens. Most expensive step.

2
SFT

Supervised Fine-Tuning on curated instruction and answer pairs so the model follows instructions.

3
Preference tuning

RLHF or DPO align answers with human preferences: helpful, honest, harmless.

4
Reasoning RL

Reinforcement learning on verifiable tasks (maths, code) teaches the model to think step by step before answering.

Prompt:   "AI will change"
Tokens:   ["AI", " will", " change"]            -> IDs (illustrative numbers)
Model:    next-token probabilities
            " the"    0.31
            " how"    0.22
            " everything" 0.09 ...
Sampling: temperature 0.7 picks " how"
Output:   "AI will change how"  -> repeat until the answer is complete

Why hallucinations happen: the model produces the most plausible continuation, not a verified fact. Grounding the model with search, RAG, tools and citations is the standard fix.

Module 2 · Machine Learning Basics

What is Machine Learning?

Machine Learning (ML) is a branch of AI where a computer learns patterns from data and uses them to make predictions or decisions on new data, without being explicitly programmed with the rules.

1
Data

Past examples (emails, prices, images).

2
Algorithm

A learning method (e.g. decision tree).

3
Training

Algorithm finds patterns in the data.

4
Model

The saved result of training.

5
Prediction

Model answers for new, unseen data.

The three families of ML
Supervised learning

Learns from labelled examples (input plus the correct answer), like a student with an answer key.

  • Classification: predict a category
  • Regression: predict a number
  • Examples: spam detection, price prediction, disease diagnosis
Unsupervised learning

Learns from unlabelled data and discovers hidden structure by itself.

  • Clustering: group similar items (customer segments)
  • Dimensionality reduction: PCA, t-SNE
  • Anomaly detection and association rules (market basket)
Reinforcement learning

An agent acts in an environment, receives rewards or penalties, and learns a policy that maximises total reward.

  • Key terms: state, action, reward, policy
  • Examples: game AI (AlphaGo), robot control, ad bidding
  • Also used to align LLMs (RLHF)
Features and labels

Features are the input variables (what the model sees). The label (or target) is the answer the model should predict. Unsupervised learning has features only.

Overfitting, Underfitting and Model Evaluation

Overfitting vs underfitting
Underfitting

Too simple. High error on both training and new data. High bias.

Good fit

Captures the real pattern and ignores noise. Low error on both. The goal.

Overfitting

Memorises noise. Very low training error but high error on new data. High variance.

UnderfittingOverfitting
SymptomTrain score low, validation score lowTrain score high, validation score much lower
CauseModel too simple, too few features, too little trainingModel too complex, too little data, noisy data, trained too long
FixesUse a stronger model, add or engineer features, train longer, reduce regularisationGet more data, simplify the model, regularisation (L1/L2, dropout), early stopping, cross-validation, data augmentation, ensembles

Bias-variance trade-off: a simple model has high bias (misses patterns). A complex model has high variance (chases noise). Good ML finds the balance in between.

Which metric to favour?

Precision when false alarms are costly (blocking real email). Recall when misses are costly (cancer screening, fraud). F1 for a balance.

Module 3 · Deep Learning and Neural Networks Explained

What is Deep Learning?

Deep Learning (DL) is a subset of machine learning that uses neural networks with many layers to learn features automatically from raw data such as pixels, audio and text. Classic ML needs humans to design features; deep learning learns them itself.

Classic MLDeep learning
FeaturesHand-crafted by humansLearned automatically
Best dataTabular, small to mediumImages, audio, text, video; very large
Data and computeModest, CPU is enoughLarge, GPU / TPU needed
InterpretabilityOften easierHarder
Neural network structure
  • Input layer: receives the raw features (pixels, numbers, tokens).
  • Hidden layers: each neuron combines inputs and passes a signal on. More layers means a "deeper" network that learns more abstract features.
  • Output layer: gives the answer: a class probability, a number or the next token.
  • Every line is a weight that training adjusts.
Neurons, weights, biases and activation functions
output = activation( w₁·x₁ + w₂·x₂ + ... + wₙ·xₙ + b )
Neuron

Small unit that takes inputs, computes a weighted sum, and applies an activation function.

Weights (w)

How important each input is. Learned during training. Large positive or negative weights mean strong influence.

Bias (b)

A learned offset that shifts the result so the neuron can activate even when all inputs are zero.

Activation function

Adds non-linearity. Without it, many layers collapse into one straight-line model.

ActivationOutput rangeTypical useNotes
Sigmoid0 to 1Binary output probabilityCan saturate and slow learning (vanishing gradient)

Forward and Back Propagation, Loss Functions and Optimizers

Training a network is a loop that repeats thousands or millions of times:

1
Forward propagation

Input flows through the layers to produce a prediction.

2
Compute loss

Compare prediction with the true answer.

3
Backpropagation

Work out how much each weight contributed to the error (gradients).

4
Optimizer step

Nudge each weight to reduce the loss.

5
Repeat

Many batches and epochs until the loss stops improving.

A tiny worked example

One weight, one input: prediction = w · x, with w = 2, x = 3, true answer y = 10, learning rate 0.01.

StepCalculation
Forwardprediction = 2 × 3 = 6
Loss (squared error)(6 − 10)² = 16
Backprop (gradient)dLoss/dw = 2 × (prediction − y) × x = 2 × (−4) × 3 = −24
Updatew = 2 − 0.01 × (−24) = 2.24 (prediction moves toward 10)

Backpropagation uses the chain rule of calculus to push the error backward from the output to every earlier layer, so all weights get their gradient in one efficient pass. Gradient descent then moves the weights a small step downhill on the loss surface.

CNN, RNN, LSTM and GRU

CNN: Convolutional Neural Networks (images)

A CNN slides small filters across an image to detect local patterns. Early layers find edges, middle layers find shapes and textures, deep layers find objects. Weights are shared across the image, so far fewer parameters are needed than with a fully connected network.

INPUT

Pixel grid (e.g. 224×224×3).

CONV

Filters produce feature maps.

POOL
Pooling

Shrinks maps, keeps key signals.

REPEAT
More conv blocks

Edges → shapes → objects.

OUT
Flatten + Dense + Softmax

Class probabilities.

  • Filter / kernel: small matrix (e.g. 3×3) of learnable weights. Stride: how far it moves each step. Padding: border added to keep size.
  • Pooling: max or average over a small window to reduce size and add tolerance to small shifts.
  • Famous models: LeNet, AlexNet, VGG, ResNet (skip connections), EfficientNet. Uses: classification, detection (YOLO), segmentation, medical imaging, OCR.

RNN: Recurrent Neural Networks (sequences)

An RNN reads a sequence one step at a time and keeps a hidden state (memory) that carries information forward. It suits ordered data such as text, speech, sensor readings and time series.

hₜ = activation( W·xₜ + U·hₜ₋₁ + b ) → the new state depends on the current input and the previous state

Problem: on long sequences, gradients shrink (vanishing gradient) or explode, so a plain RNN forgets early information. It is also slow because steps must run one after another.

LSTM and GRU
LSTM: Long Short-Term Memory

Adds a cell state (long-term memory) controlled by three gates:

  • Forget gate: what to erase
  • Input gate: what new information to store
  • Output gate: what to reveal as the output
GRU: Gated Recurrent Unit

A simpler, faster alternative with two gates and no separate cell state:

  • Update gate: how much past to keep
  • Reset gate: how much past to ignore
  • Fewer parameters, often similar accuracy to LSTM

Transformers and the Attention Mechanism

The Transformer (2017, "Attention Is All You Need") processes all tokens in parallel and lets every token look at every other token. It powers GPT, Claude, Gemini, Llama, BERT, Vision Transformers, Whisper and most modern AI.

Attention in plain words

In the sentence "The animal didn't cross the street because it was too tired", attention lets the model link "it" to "animal". Each token creates three vectors:

QQuery

"What am I looking for?"

KKey

"What do I contain?" Compared with queries to get relevance scores.

VValue

"The information I pass on." Mixed together using the attention weights.

Attention(Q, K, V) = softmax( Q·Kᵀ / √d_k ) · V
import numpy as np

def attention(Q, K, V):
    scores = Q @ K.T / np.sqrt(K.shape[-1])                   # how relevant is each token to each other
    weights = np.exp(scores - scores.max(-1, keepdims=True))
    weights /= weights.sum(-1, keepdims=True)                 # softmax: each row sums to 1
    return weights @ V                                        # weighted mix of values

tokens = np.random.rand(4, 8)          # 4 tokens, 8-dim vectors (self-attention: Q = K = V source)
print(attention(tokens, tokens, tokens).shape)   # (4, 8)

Transfer Learning, Training, Fine-tuning and Inference

Transfer learning

Instead of training from scratch, start from a model already trained on a huge dataset (e.g. ImageNet or web text) and adapt it to your smaller task. It saves data, time and money and usually gives better results.

Feature extraction

Freeze the pre-trained layers and train only a new output layer. Best with very little data.

Fine-tuning

Unfreeze some or all layers and continue training with a small learning rate. Best with more data or a different domain.

Diffusion Models, GANs and VAEs

Diffusion models

Forward process: gradually add noise to real data until it is pure noise. Reverse process: train a network to remove the noise one step at a time. To generate, start from random noise and denoise.

xₜ = √ᾱₜ · x₀ + √(1−ᾱₜ) · ε

Pros top image/video quality, stable training, flexible control

Cons many steps make it slower (distillation and fewer-step samplers help)

Examples: Stable Diffusion, FLUX, Midjourney, Imagen, Veo, Sora

GANs: Generative Adversarial Networks

Two networks compete. The generator makes fakes from random noise. The discriminator tries to tell real from fake. Each improves by beating the other, like a forger and a detective.

minG maxD E[log D(x)] + E[log(1 − D(G(z)))]

Pros very fast generation, sharp images

Cons hard to train, mode collapse (low variety), less controllable

Examples: StyleGAN faces, super-resolution, image-to-image (Pix2Pix, CycleGAN)

VAEs: Variational Autoencoders

An encoder compresses data into a small probabilistic latent space; a decoder rebuilds it. Sampling a new point in the latent space and decoding it creates new data.

Loss = reconstruction error + KL divergence

Pros stable, smooth latent space, good for compression

Cons outputs are often blurrier on their own

Examples: the encoder/decoder inside Stable Diffusion, anomaly detection, drug design

Multimodal AI and AI Content Creation Use Cases

What is multimodal AI?

Multimodal AI understands and/or generates more than one type of data (text, images, audio, video, documents, sensor data) in a single model, so you can show it a photo and ask a question by voice, then get a spoken or written answer.

How it works
  • Each modality has an encoder (image encoder, audio encoder, tokenizer) that converts input into embeddings.
  • Embeddings are projected into a shared space so a Transformer can reason across them together.
  • CLIP-style contrastive training aligns matching image and text pairs.
  • "Omni" models handle several inputs and outputs natively, including real-time speech-to-speech.
Examples of multimodal tasks
  • Photo of a fridge + "what can I cook?" → recipe
  • Screenshot of an error + "fix this" → explanation and code
  • Chart image → insights and a summary table
  • Video lecture → notes, quiz and timestamps
  • Live camera + voice → real-time visual assistant

Copyright, Deepfakes and Content Authenticity

This is educational information, not legal advice. Laws and court cases are changing fast and differ by country, so check current rules for your region and situation.

Copyright and ownership
  • Training data: many lawsuits ask whether training on copyrighted works without permission is allowed. Outcomes vary by country and are still developing.
  • Ownership of outputs: in several jurisdictions (for example the US Copyright Office's position) purely AI-generated material without meaningful human authorship may not be protected.
  • Terms of service: each tool defines commercial-use rights and who owns outputs.
  • Lower-risk tools: models trained on licensed or opt-in data and vendors that offer IP indemnity (e.g. Adobe Firefly).
Deepfakes

Synthetic faces, voices or videos that realistically imitate a real person.

  • Harms: fraud (voice-clone scams), non-consensual intimate images, election and news misinformation, reputation damage.
  • Legal trend: many countries and regions are adding laws and platform rules against harmful deepfakes.
  • Positive uses: accessibility, dubbing, film VFX, education, with consent.
Content authenticity
  • C2PA / Content Credentials: signed metadata recording how and with what tool content was made or edited.
  • Invisible watermarks: hidden signals in pixels or audio, such as Google's SynthID.
  • Labels and disclosure: platforms and regulations (e.g. EU AI Act transparency rules) increasingly require marking AI-generated content.
  • Detectors are helpful but imperfect; provenance is more reliable than guessing.
If you create with AI
  • Read the tool's licence for commercial use.
  • Do not imitate a living artist's style or a real person's face or voice without permission.
  • Add meaningful human creative input and keep your prompts, drafts and edits as records.
  • Label AI-generated or AI-edited media where required or where it could mislead.
  • Never use AI to impersonate, deceive or harass.
If you see suspicious content
  • Check the source and look for Content Credentials or an official statement.
  • Look for odd hands, text, lighting, lip-sync or voice rhythm, but do not rely on these alone.
  • Reverse-image search and compare with trusted outlets.
  • For money or urgent requests, verify through a second channel (call back on a known number, use a code word).
  • Report harmful deepfakes to the platform and, if needed, to the authorities.

Module 5 · LLMs: Tokens, Context Window, Parameters

A Large Language Model (LLM) is a very large neural network, almost always a Transformer, trained on massive text (and increasingly images, audio and code) to predict the next token. That one skill lets it write, summarise, translate, reason and code. For the step-by-step mechanics see How a Large Language Model works.

Tokens and tokenization

Models do not read letters or words. A tokenizer splits text into tokens (whole words, word pieces, punctuation, bytes) using an algorithm such as BPE (Byte Pair Encoding), then maps each to an integer ID. A vocabulary typically has 30,000 to 250,000 tokens.

Context window

The context window is the maximum number of tokens the model can handle in one request. It is the model's working memory and includes everything: system prompt, conversation history, attached documents, tool results, and the answer being generated.

Size

From a few thousand tokens in small models to hundreds of thousands, and over a million in some frontier models. Check the current limit for your model.

Trade-offs

Longer context costs more, adds latency, and models can miss details buried in the middle ("lost in the middle").

Managing it

Summarise old turns, use RAG to bring only relevant chunks, put key instructions first or last, and cache repeated prefixes.

Parameters and model size

Parameters are the learned numbers (weights and biases) inside the model. Size is quoted in billions (B) of parameters. More parameters generally mean more capacity, but data quality, training method and architecture matter just as much, and smaller modern models often beat older, larger ones.

RLHF: Reinforcement Learning from Human Feedback
1
Generate answers

The SFT model writes several answers per prompt.

2
Humans rank them

Annotators choose the best and worst.

3
Train a reward model

It learns to score answers like humans do.

4

The LLM is tuned (e.g. PPO) to earn higher reward, with a penalty for drifting too far from the original.

  • DPO (Direct Preference Optimization): trains directly on chosen vs rejected pairs, with no separate reward model or RL loop, so it is simpler and cheaper.
  • RLAIF / Constitutional AI: an AI judge guided by written principles supplies some of the feedback.
  • RLVR: RL with verifiable rewards (unit tests, correct maths answers) for reasoning models.
  • Risk: over-optimising can make the model flattering ("sycophantic") or reward-hacking, so evaluation matters.

Module 6 · Prompt Engineering: Anatomy of a Good Prompt

Prompt engineering is the practice of designing and refining the input (instructions, context, examples and format) you give a generative AI model so it produces accurate, useful and consistent output. A prompt is effectively a small program written in natural language.

The six building blocks
1Role

Who the model should act as. "You are a senior data analyst."

2Task

The exact job, using a clear verb. "Summarise this report for a CEO."

3Context

Background the model cannot guess: audience, goal, data, documents, situation.

4Constraints

Rules and limits: length, tone, scope, what to avoid, what to do when unsure.

5Output format

How the answer should look: bullets, table, JSON, markdown, code only, language.

6Examples (optional)

One to three sample inputs and outputs that show the exact style wanted.

Weak vs strong prompt
Weak prompt
-----------
Tell me about Laravel.

Vague: unknown audience, length, depth and format, so the answer is generic.

[ROLE]        You are a senior PHP trainer.
[TASK]        Explain Laravel routing.
[CONTEXT]     The reader is a beginner who knows core PHP but has never used a framework.
[CONSTRAINTS] Max 300 words. No jargon without a one-line explanation.
              If unsure about a version detail, say so instead of guessing.
[FORMAT]      Markdown with headings: Definition, 3 code examples, Common mistake.

Specific: the model knows who it is, who it is writing for, and exactly what to return.

Module 7 · What is an AI Agent?

An AI agent is a system in which an LLM is given a goal, can use tools to act on the world, observes the results, and decides its own next steps in a loop until the goal is reached. A chatbot answers; an agent gets things done.

Agent components
1. LLM (the brain)

Understands the goal, reasons, and decides the next action. Stronger models plan and use tools more reliably; smaller ones are cheaper for simple steps.

2. Instructions (system prompt)

Role, rules, tone, tool-usage policy, when to ask the user, when to stop.

3. Memory

Short-term: the current context and scratchpad. Long-term: notes, user preferences and past tasks stored in files, a database or a vector DB and recalled when needed.

4. Tools

Functions the agent can call: web search, databases, email, calendar, code runner, browser, file access, MCP servers.

5. Planning

Breaks a goal into steps. Patterns: ReAct (think, act, observe), plan-and-execute, and reflection (review and improve its own work).

6. Actions and environment

The agent's tool calls change something (send, write, click) and the result comes back as an observation that feeds the next decision.

7. Guardrails and human oversight

Permissions, input and output checks, budgets, step limits and human approval for risky actions.

8. Runtime (orchestrator)

The code that runs the loop, keeps state, retries failures, logs every step and stops the agent.

The agent loop
1
Goal

User request or trigger (schedule, webhook, message).

2
Think / Plan

LLM reads goal, memory and tools, decides the next step.

3
Act

Calls a tool with arguments.

4
Observe

Result or error returns to the model.

5
Decide

Goal met? Finish and answer. Otherwise loop back to step 2.

Tool Calling / Function Calling

Tool calling lets an LLM request that your code run a function. The model never runs anything itself: it outputs a structured request (function name and JSON arguments), your program executes it, and you send the result back so the model can continue.

1
Describe tools

Send each tool's name, description and JSON-schema parameters with the prompt.

2
Model decides

Replies with a tool call, e.g. get_weather({"city":"Pune"}), or a normal answer.

3
You execute

Validate the arguments and run the real function or API.

4
Return the result

Append a "tool" message with the output and call the model again.

5
Final answer

Model uses the result to reply, or asks for another tool.

# pip install openai    (the same idea works with Claude, Gemini, Mistral, Ollama, OpenRouter...)
import json
from openai import OpenAI

client = OpenAI()

def get_weather(city: str) -> str:                       # your real function
    return json.dumps({"city": city, "temp_c": 28, "sky": "sunny"})

tools = [{
    "type": "function",
    "function": {
        "name": "get_weather",
        "description": "Get the current weather for a city.",
        "parameters": {
            "type": "object",
            "properties": {"city": {"type": "string", "description": "City name, e.g. Pune"}},
            "required": ["city"],
        },
    },
}]

messages = [{"role": "user", "content": "Do I need an umbrella in Pune today?"}]
first = client.chat.completions.create(model="gpt-4o-mini", messages=messages, tools=tools)
msg = first.choices[0].message

if msg.tool_calls:                                       # the model asked to use a tool
    messages.append(msg)
    for call in msg.tool_calls:
        args = json.loads(call.function.arguments)
        messages.append({"role": "tool", "tool_call_id": call.id, "content": get_weather(**args)})
    final = client.chat.completions.create(model="gpt-4o-mini", messages=messages, tools=tools)
    print(final.choices[0].message.content)
else:
    print(msg.content)
Writing good tools
  • Clear names and descriptions: the description is the model's only manual. Say when to use it and when not to.
  • Small, focused tools with simple typed parameters and enums where possible.
  • Return short, useful text or JSON, not huge dumps. Include error messages the model can act on.
  • Validate arguments in your code; never trust model output blindly.
  • Make risky tools safe: read-only by default, confirmation for send, delete or pay.
Useful options and ideas
  • tool_choice: let the model decide (auto), force a tool call (required), force one named tool, or disable tools.
  • Parallel tool calls: a model may request several independent calls at once. Run them together.
  • Structured outputs / strict mode make arguments match your schema more reliably.
  • MCP standardises tools so one server (GitHub, files, databases) works in many agent apps. See RAG, agents and MCP.
  • Other providers use similar concepts under different field names (for example Claude's tool_use blocks). Check their docs.

from bs4 import BeautifulSoup

def web_search(query: str, max_results: int = 5) -> str:

        "https://api.tavily.com/search",

import subprocess, tempfile, pathlib

def run_python(code: str, timeout: int = 15) -> str:
    """Run Python in a locked-down Docker container and return its output."""
    with tempfile.TemporaryDirectory() as d:
        (pathlib.Path(d) / "main.py").write_text(code)
        cmd = ["docker", "run", "--rm", "--network", "none", "--memory", "256m", "--cpus", "0.5",
               "-v", f"{d}:/work:ro", "-w", "/work", "python:3.12-slim", "python", "main.py"]
        try:
            p = subprocess.run(cmd, capture_output=True, text=True, timeout=timeout)
        except subprocess.TimeoutExpired:
            return "Error: execution timed out"
        return (p.stdout + p.stderr)[-4000:]        # return the tail so the model sees the error

        if action["type"] == "type":   page.fill(action["selector"], action["text"])
        if action["type"] == "goto":   page.goto(action["url"])
        page.wait_for_load_state()
    browser.close()
  • Start with read-only tasks. Require approval for logins, purchases, posting and deleting.
  • Use a separate browser profile and test accounts, never your main logged-in profile.
  • Prefer an official API over clicking through a website whenever one exists; it is faster, cheaper and more reliable.

Multi-agent Systems, Agent Workflows and Orchestration

A multi-agent system uses several specialised agents (each with its own instructions, tools and sometimes its own model) that cooperate on one task, like a small team: a planner, a researcher, a coder and a reviewer.

Common multi-agent patterns
PatternHow it worksGood for
Orchestrator / supervisor + workersA lead agent splits the task, delegates to worker agents and merges their resultsResearch, report writing, complex coding tasks
Sequential pipelineAgent A's output feeds Agent B, then CResearcher → writer → editor

Use multiple agents when
  • Sub-tasks need different tools, permissions or expertise
  • One agent's context would get too large or confusing
  • You want independent review (maker and checker)
  • Work can run in parallel to save time
Watch out for
  • Cost and latency multiply with every agent
  • Error cascade: one wrong output poisons the next agent
  • Lost context between agents; share state explicitly
  • Hard to debug without tracing. Start with one agent and add more only when it clearly helps.
Agent workflows and orchestration patterns

Orchestration is the layer that controls who runs when, passes state between steps, handles failures, and keeps humans in the loop. These five workflow patterns (popularised in Anthropic's "Building effective agents") cover most needs:

1Prompt chaining

Fixed sequence of LLM steps, with checks between them. Extract → Validate → Write

2Routing

Classify the input and send it to the right specialised prompt, tool or model.

3Parallelisation

Run independent sub-tasks at the same time, or run the same task several times and vote.

4Orchestrator-workers

A manager LLM decides the sub-tasks dynamically and assigns them to worker LLMs.

5Evaluator-optimizer

Generate, evaluate against criteria, improve, repeat until good enough.

6Autonomous agent loop

Open-ended tool loop with environment feedback, used only when steps cannot be predicted.

Production orchestration checklist
  • State: one shared, typed state object that every step reads and updates.
  • Reliability: timeouts, retries with back-off, fallbacks to another model, idempotent tool calls.
  • Human-in-the-loop: pause for approval or edits, then resume from the saved checkpoint.
  • Observability: trace every prompt, tool call, cost and latency (Langfuse, LangSmith, Arize Phoenix).
  • Durability: long jobs run in queues or workflow engines (Temporal, Celery, cloud queues) so a crash does not lose work.

import ast, datetime, json, operator as op, os, pathlib
import requests
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()
client = OpenAI()                      # reads OPENAI_API_KEY from the environment
MODEL = "gpt-4o-mini"                  # use any model that supports tool calling
NOTES = pathlib.Path("notes.json")

# ---------- 1. TOOLS: plain Python functions ----------
OPS = {ast.Add: op.add, ast.Sub: op.sub, ast.Mult: op.mul, ast.Div: op.truediv,
       ast.Pow: op.pow, ast.USub: op.neg}

def _eval(node):
    if isinstance(node, ast.Constant) and isinstance(node.value, (int, float)):
        return node.value
    if isinstance(node, ast.BinOp) and type(node.op) in OPS:
        return OPS[type(node.op)](_eval(node.left), _eval(node.right))
    if isinstance(node, ast.UnaryOp) and type(node.op) in OPS:
        return OPS[type(node.op)](_eval(node.operand))
    raise ValueError("unsupported expression")

def calculator(expression: str) -> str:
    return str(_eval(ast.parse(expression, mode="eval").body))      # safe: no eval()

def get_datetime() -> str:
    return datetime.datetime.now().strftime("%A, %d %B %Y, %H:%M")

def save_note(text: str) -> str:
    notes = json.loads(NOTES.read_text()) if NOTES.exists() else []
    notes.append({"time": get_datetime(), "text": text})
    NOTES.write_text(json.dumps(notes, indent=2))
    return "Note saved."

def list_notes() -> str:
    return NOTES.read_text() if NOTES.exists() else "No notes yet."

def web_search(query: str) -> str:                                  # optional third-party tool (Tavily)
    key = os.getenv("TAVILY_API_KEY")
    if not key:
        return "Web search is not configured."
    r = requests.post("https://api.tavily.com/search", headers={"Authorization": f"Bearer {key}"},
                      json={"query": query, "max_results": 4}, timeout=20)
    r.raise_for_status()
    return "\n\n".join(f"{x['title']} ({x['url']})\n{x['content']}" for x in r.json()["results"])

REGISTRY = {"calculator": calculator, "get_datetime": get_datetime, "save_note": save_note,
            "list_notes": list_notes, "web_search": web_search}

def schema(name, description, props=None, required=()):
    return {"type": "function", "function": {"name": name, "description": description,
            "parameters": {"type": "object", "properties": props or {}, "required": list(required)}}}

TOOLS = [
    schema("calculator", "Evaluate a maths expression, e.g. 12*(3+4). Use it for any arithmetic.",
           {"expression": {"type": "string"}}, ["expression"]),
    schema("get_datetime", "Get the current local date and time."),
    schema("save_note", "Save a note or fact the user wants remembered.",
           {"text": {"type": "string"}}, ["text"]),
    schema("list_notes", "Read all saved notes."),
    schema("web_search", "Search the web for current information. Use for news and facts that may have changed.",
           {"query": {"type": "string"}}, ["query"]),
]

# ---------- 2. INSTRUCTIONS ----------
SYSTEM = """You are Nova, my personal assistant.
- Use tools when they help; never guess dates, maths or current facts.
- When I say "remember ...", call save_note.
- Be concise. If a tool fails or you are unsure, say so instead of inventing an answer."""

# ---------- 3. THE AGENT LOOP ----------
def run_agent(user_msg, history, max_steps=6):
    messages = [{"role": "system", "content": SYSTEM}] + history + [{"role": "user", "content": user_msg}]
    for _ in range(max_steps):                                      # hard limit prevents endless loops
        resp = client.chat.completions.create(model=MODEL, messages=messages, tools=TOOLS)
        msg = resp.choices[0].message
        messages.append(msg)
        if not msg.tool_calls:                                      # no tool needed: this is the final answer
            return msg.content, messages[1:]
        for call in msg.tool_calls:
            fn = REGISTRY.get(call.function.name)
            try:
                result = fn(**json.loads(call.function.arguments)) if fn else "Unknown tool."
            except Exception as e:                                  # give errors back so the model can recover
                result = f"Tool error: {e}"
            print(f"  [tool] {call.function.name}({call.function.arguments}) -> {str(result)[:80]}")
            messages.append({"role": "tool", "tool_call_id": call.id, "content": str(result)})
    return "I stopped because I reached my step limit.", messages[1:]

# ---------- 4. CHAT IN THE TERMINAL ----------
if __name__ == "__main__":
    history = []
    while True:
        text = input("You: ").strip()
        if text.lower() in {"exit", "quit"}:
            break
        answer, history = run_agent(text, history)
        history = history[-30:]                                     # keep the context small
        print("Nova:", answer, "\n")

2Long-term memory with embeddings (SQLite)
import json, sqlite3
import numpy as np

db = sqlite3.connect("memory.db")
db.execute("CREATE TABLE IF NOT EXISTS mem (id INTEGER PRIMARY KEY, text TEXT, vec TEXT)")

def embed(text: str):
    return client.embeddings.create(model="text-embedding-3-small", input=text).data[0].embedding

def remember(text: str) -> str:
    db.execute("INSERT INTO mem(text, vec) VALUES (?, ?)", (text, json.dumps(embed(text))))
    db.commit()
    return "Remembered."

def recall(query: str, k: int = 3) -> str:
    q = np.array(embed(query))
    rows = db.execute("SELECT text, vec FROM mem").fetchall()
    scored = sorted(((float(q @ np.array(json.loads(v))), t) for t, v in rows), reverse=True)   # dot product = cosine (unit vectors)
    return "\n".join(t for _, t in scored[:k]) or "Nothing relevant."

3Plan, act, review loop with LangGraph
# pip install langgraph
from typing import TypedDict
from langgraph.graph import StateGraph, START, END

def ask(prompt: str) -> str:                                  # single LLM call, no tools
    r = client.chat.completions.create(model=MODEL, messages=[{"role": "user", "content": prompt}])
    return r.choices[0].message.content

class S(TypedDict, total=False):
    goal: str; plan: str; result: str; feedback: str; attempts: int

def planner(s):
    return {"plan": ask(f"Write a short numbered plan to achieve: {s['goal']}\nPrevious feedback: {s.get('feedback', 'none')}")}

def executor(s):
    answer, _ = run_agent(f"Goal: {s['goal']}\nFollow this plan:\n{s['plan']}", [])      # reuse the tool-using agent
    return {"result": answer, "attempts": s.get("attempts", 0) + 1}

def reviewer(s):
    return {"feedback": ask(f"Goal: {s['goal']}\nResult: {s['result']}\nReply exactly PASS if the goal is fully met, otherwise list what is missing.")}

def route(s):
    return END if s["feedback"].strip().startswith("PASS") or s["attempts"] >= 3 else "planner"   # max 3 tries

g = StateGraph(S)
g.add_node("planner", planner); g.add_node("executor", executor); g.add_node("reviewer", reviewer)
g.add_edge(START, "planner"); g.add_edge("planner", "executor"); g.add_edge("executor", "reviewer")
g.add_conditional_edges("reviewer", route, {END: END, "planner": "planner"})
app = g.compile()

print(app.invoke({"goal": "Prepare my weekly plan from my saved notes"})["result"])

Module 8 · AI Models: What They Are, Foundation Models, Open-weight Models

An AI model is a mathematical function stored as a file. It has an architecture (the layout of the network) and weights (billions of learned numbers). You feed it input, it computes an output: a label, a number, text, an image, a vector. Training creates the file; inference uses it.

What you actually get when you "download a model"
  • Weights file(s): .safetensors (Hugging Face standard), .gguf (llama.cpp / Ollama, quantised), .onnx (portable), .pt (PyTorch).
  • Config and tokenizer: architecture settings and the vocabulary.
  • Model card: intended use, training data summary, benchmarks, limits and the licence. Always read it.
Two ways to use any model
  • Hosted API: a company runs the model; you send HTTPS requests and pay per use. Fast to start, no hardware.
  • Self-hosted: you download open weights and run them on your laptop or server. Private, no per-token fee, but you manage hardware.
  • Many apps use both: a hosted frontier model for hard tasks and a small local model for cheap or private ones.

Foundation models

A foundation model is a very large model pre-trained on broad data so that one model can be adapted to many tasks, by prompting, RAG, fine-tuning or tool use, instead of training a new model per task. Examples: GPT, Claude, Gemini, Llama (language and multimodal), Stable Diffusion and FLUX (images), Whisper (speech), CLIP (image-text).

Rate Limits, Tokens and Pricing

Tokens and pricing
  • You pay per token, usually quoted per 1 million tokens, with separate prices for input (prompt) and output (answer). Output is typically several times more expensive.
  • Input includes the whole history, system prompt, retrieved documents and tool results, so long chats cost more each turn.
  • Reasoning models bill hidden "thinking" tokens as output.
  • Discounts: cached (repeated) prompt prefixes, batch APIs (often about 50% cheaper, results within hours), and smaller models.
  • Images, audio and video are billed by size or duration, embeddings by input tokens.
Rate limits

Providers cap usage so the service stays fair. Limits depend on your account tier and the model.

  • RPM: requests per minute
  • TPM: tokens per minute (input plus output)
  • RPD: requests per day (common on free tiers)
  • Concurrency and monthly spend caps
  • Exceeding them returns HTTP 429. Look for Retry-After and rate-limit headers in the response.

Handle rate limits: retry with exponential back-off
import random, time
from openai import OpenAI, RateLimitError, APIConnectionError, APIStatusError

client = OpenAI(max_retries=0)              # we handle retries ourselves (the SDK also has max_retries built in)

def chat_with_retry(messages, model="gpt-4o-mini", tries=5):
    for attempt in range(tries):
        try:
            return client.chat.completions.create(model=model, messages=messages, timeout=60)
        except (RateLimitError, APIConnectionError):
            pass                                                    # temporary: wait and retry
        except APIStatusError as e:
            if e.status_code < 500:
                raise                                               # 4xx other than 429: fix the request instead
        time.sleep(min(2 ** attempt + random.random(), 30))         # 1s, 2s, 4s... plus jitter
    raise RuntimeError("API still failing after retries")
Common HTTP errors

404Wrong URL or model name

500 / 503Provider problem: retry with back-off, fall back to another model
Cut cost and stay under limits
  • Use the smallest model that passes your tests; route hard cases to a bigger one.
  • Cache answers for repeated questions and use provider prompt caching.
  • Trim history, send only relevant chunks (RAG), and set max_tokens.
  • Use queues and per-user quotas so one user cannot burn the budget.
  • Use batch endpoints for non-urgent jobs; log usage for every call.

Streaming Responses, Structured JSON Output and Function Calling

Streaming responses

Without streaming, the user waits for the whole answer. With stream: true the server sends the answer in small chunks as Server-Sent Events (SSE), so text appears word by word. It feels much faster (low time to first token) and lets users stop early.

stream = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Write a haiku about APIs."}],
    stream=True,
)
for chunk in stream:
    if chunk.choices and chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="", flush=True)
What the wire looks like (SSE)

data: {"choices":[{"delta":{"content":"Hel"}}]}

data: {"choices":[{"delta":{"content":"lo"}}]}

data: {"choices":[{"delta":{},"finish_reason":"stop"}]}

data: [DONE]
  • Browsers can read a streamed fetch() response with response.body.getReader(). EventSource only supports GET.
  • Behind Nginx or a proxy, disable buffering (X-Accel-Buffering: no, proxy_buffering off) or chunks arrive all at once.
  • Token usage appears in the final chunk only if you request it (e.g. stream_options: {"include_usage": true} on OpenAI).
  • A complete Laravel streaming controller and browser client are in Chatbot in Laravel.
Structured JSON output

Apps need data, not paragraphs. Three levels of reliability, from weakest to strongest: (1) ask for JSON in the prompt, (2) JSON mode (valid JSON, any shape), (3) schema-constrained output (valid JSON that matches your JSON Schema). Always validate in your own code as well.

import json
from pydantic import BaseModel

class Invoice(BaseModel):
    vendor: str
    invoice_number: str
    total: float
    currency: str

schema = {
    "type": "object",
    "properties": {
        "vendor": {"type": "string"}, "invoice_number": {"type": "string"},
        "total": {"type": "number"},  "currency": {"type": "string"},
    },
    "required": ["vendor", "invoice_number", "total", "currency"],
    "additionalProperties": False,
}

resp = client.chat.completions.create(

Production checklist
  • Hardware: VRAM decides which model fits; add headroom for the KV cache and concurrent users.
  • Never expose the raw model port to the internet; use TLS, authentication and rate limits.
  • Pin model versions and keep weights on a persistent volume.
  • Queue long jobs and cap concurrency so requests do not time out.

Self-host or use an API?

<?php
// app/Services/Ai/GeminiClient.php
namespace App\Services\Ai;

use App\Contracts\AiClient;
use Illuminate\Support\Facades\Http;

class GeminiClient implements AiClient
{
    public function chat(array $messages, array $options = []): string
    {
        $model  = $options['model'] ?? config('services.gemini.model');
        $system = collect($messages)->firstWhere('role', 'system')['content'] ?? null;

        $contents = collect($messages)->where('role', '!=', 'system')
            ->map(fn ($m) => [
                'role'  => $m['role'] === 'assistant' ? 'model' : 'user',
                'parts' => [['text' => $m['content']]],
            ])->values()->all();

        $payload = ['contents' => $contents, 'generationConfig' => ['temperature' => $options['temperature'] ?? 0.3]];
        if ($system) {
            $payload['systemInstruction'] = ['parts' => [['text' => $system]]];
        }

        return Http::withHeaders(['x-goog-api-key' => config('services.gemini.key')])
            ->timeout(60)
            ->post("https://generativelanguage.googleapis.com/v1beta/models/{$model}:generateContent", $payload)
            ->throw()
            ->json('candidates.0.content.parts.0.text');
    }
}

use Illuminate\Support\Facades\Http;

class OpenAiStreamer
{
    /** Yields each piece of text as the model produces it. */
    public function stream(array $messages): Generator
    {
        $response = Http::withToken(config('services.openai.key'))
            ->withOptions(['stream' => true])
            ->timeout(120)
            ->post('https://api.openai.com/v1/chat/completions', [
                'model'    => config('services.openai.model'),
                'messages' => $messages,
                'stream'   => true,
            ])
            ->throw();

        $body = $response->toPsrResponse()->getBody();
        $buffer = '';

        while (! $body->eof()) {
            $buffer .= $body->read(1024);

            while (($pos = strpos($buffer, "\n")) !== false) {
                $line   = trim(substr($buffer, 0, $pos));
                $buffer = substr($buffer, $pos + 1);

                if (! str_starts_with($line, 'data: ')) continue;
                $data = substr($line, 6);
                if ($data === '[DONE]') return;

                $delta = json_decode($data, true)['choices'][0]['delta']['content'] ?? '';
                if ($delta !== '') yield $delta;
            }
        }
    }
}

// Reciprocal Rank Fusion: merge any number of ranked id lists (best first)
function reciprocalRankFusion(array ...$rankings): array
{
    $scores = [];
    foreach ($rankings as $list) {
        foreach (array_values($list) as $rank => $id) {
            $scores[$id] = ($scores[$id] ?? 0) + 1 / (60 + $rank + 1);
        }
    }
    arsort($scores);
    return array_keys($scores);
}

Vector search in PHP / Laravel

Steps: chunk your content, embed each chunk, store the vectors, then at search time embed the query and fetch the nearest vectors (cosine distance). Pick the storage by scale:

<?php
// app/Services/EmbeddingService.php
namespace App\Services;

use Illuminate\Support\Facades\Http;

class EmbeddingService
{
    /** @param string[] $texts @return array<int, float[]> */
    public function embed(array $texts): array
    {
        $res = Http::withToken(config('services.openai.key'))
            ->timeout(60)->retry(3, 1000)
            ->post('https://api.openai.com/v1/embeddings', [
                'model' => 'text-embedding-3-small',          // 1536 dimensions; keep it the same for indexing and search
                'input' => $texts,                             // batch many texts in one request
            ])->throw();

        return collect($res->json('data'))->sortBy('index')->pluck('embedding')->values()->all();
    }

    /** Split long text into overlapping chunks (about 800 characters, 100 overlap). */
    public function chunk(string $text, int $size = 800, int $overlap = 100): array
    {
        $chunks = [];
        for ($i = 0, $n = mb_strlen($text); $i < $n; $i += ($size - $overlap)) {
            $chunks[] = trim(mb_substr($text, $i, $size));
        }
        return array_values(array_filter($chunks));
    }
}

// semantic search (cosine distance operator is <=>)
public function search(string $query, int $tenantId, EmbeddingService $emb, int $limit = 5): array
{
    $vec = json_encode($emb->embed([$query])[0]);

    return DB::select(
        'SELECT id, document_id, content, 1 - (embedding <=> ?::vector) AS score
         FROM document_chunks
         WHERE tenant_id = ?
         ORDER BY embedding <=> ?::vector
         LIMIT ?',
        [$vec, $tenantId, $vec, $limit]
    );
}

function cosine(array $a, array $b): float
{
    $dot = $na = $nb = 0.0;
    foreach ($a as $i => $x) {
        $dot += $x * $b[$i];
        $na  += $x * $x;
        $nb  += $b[$i] * $b[$i];
    }
    return $dot / (sqrt($na) * sqrt($nb) + 1e-12);
}

{

}
Design decisions
  • Fail closed or open? For public or child-facing apps block when the check fails; for low-risk internal tools you may allow and log.
  • Thresholds: allow, warn, hold for review, or block depending on severity and category.
  • Also moderate AI output and generated images, not only user input.
  • Keep an audit log (who, what category, decision) but avoid storing more personal data than needed.
  • Provide user reporting and a way to appeal wrong blocks.
Related safeguards
  • Prompt-injection defence: delimit user and retrieved text, never let it change system rules, limit tools.
  • PII: detect and mask emails, phone numbers and IDs before sending to a provider.
  • Image uploads: use an image moderation service and validate file types and size.
  • Test it: maintain a set of safe and unsafe examples and re-run it whenever you change policy or provider.

MCP and A2A: Connecting AI to Tools, and Agents to Agents

MCP: Model Context Protocol

An open standard (introduced by Anthropic, now supported across the industry) for connecting an AI app to tools and data. Think of it as USB-C for AI: write an integration once as an MCP server, then use it from any MCP-capable client.

A2A: Agent2Agent protocol

An open protocol (started by Google, now under the Linux Foundation) that lets one agent discover and delegate work to another agent, even from a different vendor or framework, without sharing internal memory or tools.

MCPA2A
ConnectsAgent ↔ tools, files, databases, APIsAgent ↔ agent
Other side isA deterministic capability (function, data source)An autonomous peer that reasons and may take time
Core objectsTools, resources, promptsAgent Card, tasks, messages, artifacts
Transportstdio (local) or streamable HTTP (remote), JSON-RPCHTTP with JSON-RPC, streaming via SSE
AnalogyA worker using a toolboxA manager delegating to another specialist
TogetherA planner agent uses A2A to delegate to a specialist agent, and that specialist uses MCP to reach its tools and data.
MCP architecture
  HOST (the AI app: Claude Desktop, VS Code, Cursor, your agent)
   ├── MCP client 1 ──stdio──►  MCP server: Filesystem   (tools: read_file, write_file)
   ├── MCP client 2 ──stdio──►  MCP server: Notes (yours) (tools: add_note · resources: notes://all)
   └── MCP client 3 ──HTTPS──►  MCP server: GitHub / Postgres / Slack (remote)

   Server exposes:  TOOLS (actions the model may call) · RESOURCES (readable data) · PROMPTS (reusable templates)
Example: build your own MCP server (Python)

Use case: let any AI app save and read your personal notes. Install: pip install "mcp[cli]"

# notes_server.py
import json, pathlib
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("notes")
FILE = pathlib.Path.home() / "mcp_notes.json"

def _load() -> list:
    return json.loads(FILE.read_text()) if FILE.exists() else []

@mcp.tool()
def add_note(text: str) -> str:
    """Save a short note. Use when the user asks you to remember or write something down."""
    notes = _load()
    notes.append(text)
    FILE.write_text(json.dumps(notes, indent=2))
    return f"Saved. You now have {len(notes)} notes."

@mcp.tool()
def search_notes(keyword: str) -> list[str]:
    """Return saved notes that contain the keyword (case-insensitive)."""
    return [n for n in _load() if keyword.lower() in n.lower()]

@mcp.resource("notes://all")
def all_notes() -> str:
    """Every saved note, one per line."""
    return "\n".join(_load())

@mcp.prompt()
def weekly_review() -> str:
    return "Read notes://all and summarise my notes into 5 bullets plus 3 follow-up tasks."

if __name__ == "__main__":
    mcp.run()          # stdio transport: the client launches this script

MCP security: an MCP server runs code with your permissions, and its tool descriptions are read by the model, so a malicious server can attempt "tool poisoning". Install only trusted servers, give read-only access first, restrict folders and database users, require approval for write and delete tools, and never put secrets in prompts. See prompt injection security.

The client agent fetches the remote agent's Agent Card (JSON at a well-known URL).

2

3

4

Status events and partial results; the agent may ask for more input.

Final outputs (text, files, JSON) come back as artifacts.

Example system: a Trip Planner agent receives "Plan a 3-day Delhi trip under ₹30,000". It reads the Agent Cards of a Flight agent and a Hotel agent, sends each a task via A2A, waits for their artifacts, and combines them into one itinerary. Each specialist keeps its own tools (via MCP), prompts and data private.

A2A and MCP are young and still evolving, and SDK names and method names change between versions. Check the current specifications and official SDKs before building. Start with one agent and MCP tools; add A2A only when agents really belong to different teams or vendors.

Vibe coding

Vibe coding (a term popularised by Andrej Karpathy in 2025) means building software by describing what you want in plain language, letting an AI write the code, and iterating on the result by running it and giving feedback, often without reading every line. It is excellent for prototypes and risky for production without review.

One change per prompt; commit working states to Git.

Build a habit tracker web app. Users sign up with email, add habits (name, target days per week),

from openai import OpenAI

EXTRACT_PROMPT = """From the conversation, extract durable facts worth remembering about the USER
(preferences, goals, constraints, personal context they chose to share). Ignore small talk,
one-off requests and anything sensitive (passwords, payment, health, government IDs).
Return JSON: {"memories": [{"text": "...", "importance": 1-5}]}. Return an empty list if nothing qualifies."""

def extract_memories(user_msg: str, assistant_msg: str) -> list[dict]:
    r = client.chat.completions.create(
        model="gpt-4o-mini", temperature=0, response_format={"type": "json_object"},
        messages=[{"role": "system", "content": EXTRACT_PROMPT},
                  {"role": "user", "content": f"USER: {user_msg}\nASSISTANT: {assistant_msg}"}],
    )
    return json.loads(r.choices[0].message.content).get("memories", [])

def build_system_prompt(base: str, user_id: str, new_message: str) -> str:
    memories = recall(user_id, new_message, k=5)          # embedding search over stored memories (see the SQLite / pgvector examples)
    block = "\n".join(f"- {m}" for m in memories) or "- (nothing yet)"
    return f"{base}\n\nWhat you know about this user (may be outdated; do not mention unless relevant):\n{block}"

# Example
# User: "I'm vegetarian and I have a nut allergy. Suggest dinner ideas."
# -> stored: "Vegetarian", "Allergic to nuts" (importance 5)
# Two weeks later: "What should I cook tonight?" -> the answer avoids meat and nuts without being reminded.
Design rules
  • Be selective: store facts, not whole transcripts. Merge or update duplicates and contradictions (the newest wins).
  • Summarise long histories into a rolling summary plus the last few raw messages.
  • Add importance, recency and last-used fields to rank and expire memories.
  • Never inject memories blindly: they can be wrong or stale, so phrase them as hints.
Privacy and tools
  • Let users view, edit and delete their memories, and tell them what you store (consent, DPDP and GDPR).
  • Do not store secrets or sensitive categories; isolate memories per user and per tenant.
  • Libraries and services: Mem0, Zep, Letta (MemGPT), LangGraph memory store, or your own table with pgvector. In Laravel: a memories table (user_id, content, embedding, importance, last_used_at) and the vector search code above.
Context engineering: managing everything the model sees

Context engineering is deciding what information goes into the model's context window at each step, and in what form. A good prompt is only one part: instructions, tools, retrieved documents, memory and history all compete for limited, costly space. Models perform worse when the context is long, noisy or contradictory ("context rot").

Context partExample budget (16k window)How to manage it
System instructions and rules~800 tokensShort, specific, stable (also enables prompt caching)
Tool definitions~1,500 tokensExpose only the tools needed for this step
Memory and user profile~500 tokensTop-k relevant facts only
Retrieved documents (RAG)~6,000 tokensRerank, keep the best 3-5 chunks, cite sources
Conversation history~3,000 tokensLast turns verbatim, older turns summarised
Tool results~2,000 tokensTrim or summarise large outputs; keep IDs for follow-up
Reserved for the answer~2,000 tokensSet max_tokens deliberately
Select

Retrieve only relevant facts and tools; use reranking and filters.

Compress

Summarise history, trim tool output, drop duplicates.

Isolate

Give each sub-agent its own small context; return only a summary.

Structure

Label sections (<rules>, <documents>), put key rules first or last, keep a stable prefix for caching.

import tiktoken
enc = tiktoken.get_encoding("cl100k_base")
tokens = lambda s: len(enc.encode(s))

def build_context(rules, memories, docs, history, user_msg, budget=12000):
    """Fill the window by priority: rules and user message first, then memory, docs, then as much history as fits."""
    parts, used = [], 0

    def add(label, text):
        nonlocal used
        n = tokens(text)
        if used + n <= budget:
            parts.append(f"<{label}>\n{text}\n</{label}>")
            used += n
            return True
        return False

    add("rules", rules)
    add("user_message", user_msg)
    add("memory", "\n".join(memories[:5]))
    for i, d in enumerate(docs[:5], 1):                 # docs are already reranked, best first
        if not add(f"document_{i}", d):
            break
    for turn in reversed(history[-12:]):                # newest turns first
        if not add("history", turn):
            break
    return "\n\n".join(parts)

Before and after: sending a 40-page PDF plus the entire chat on every question makes answers slow, costly and vague. Retrieving the 4 best passages, a 5-line memory block and a summarised history makes them faster, cheaper and more accurate. See also prompt engineering and the context window.

import json, re
from pydantic import BaseModel, ValidationError

PII = {"card": re.compile(r"\b(?:\d[ -]?){13,16}\b"), "email": re.compile(r"[\w.+-]+@[\w-]+\.[\w.]+")}
OFF_TOPIC = ("ignore previous instructions", "reveal your system prompt")

class Reply(BaseModel):
    answer: str
    sources: list[str]

def check_input(text: str) -> str:
    if len(text) > 4000:
        raise ValueError("Message too long.")
    if any(p in text.lower() for p in OFF_TOPIC):
        raise ValueError("I can't help with that request.")
    for name, rx in PII.items():
        text = rx.sub(f"[{name} removed]", text)               # mask before it reaches the model or the logs
    return text

def guarded_answer(user_text: str) -> str:
    try:
        clean = check_input(user_text)
    except ValueError as e:
        return str(e)

    for attempt in range(2):                                    # one retry on bad output
        raw = call_llm_json(clean)                              # your LLM call returning a JSON string
        try:
            reply = Reply(**json.loads(raw))
        except (ValidationError, json.JSONDecodeError):
            continue
        if not reply.sources:                                   # policy: every answer must cite something
            continue
        return reply.answer
    return "Sorry, I couldn't produce a reliable answer. Please contact support."

Prompt injection security

Prompt injection is when text the model reads contains instructions that override your intent. It is the top-ranked risk in the OWASP Top 10 for LLM applications, and it cannot be fully eliminated, only contained by design.

Output filter: remove external images and links (data-exfiltration route)

import re
ALLOWED = ("https://cdn.myapp.com/", "https://myapp.com/")

def strip_untrusted_urls(markdown: str) -> str:
    def repl(m):
        return m.group(0) if m.group(2).startswith(ALLOWED) else "[link removed]"
    # matches both ![image](url) and [text](url)
    return re.sub(r"(!?\[[^\]]*\]\()([^)\s]+)([^)]*\))", repl, markdown)
The "lethal trifecta": avoid combining all three
  • Access to private data (email, files, database)
  • Exposure to untrusted content (web, inbound email, uploads)
  • Ability to communicate externally (send email, call URLs, post)

If an agent has all three, an injected instruction can steal data. Remove at least one, or add human approval.

Testing checklist
  • Keep a red-team set of known jailbreaks and indirect attacks and run it in CI (promptfoo and similar tools can generate them).
  • Plant a canary instruction in a test document and confirm the agent ignores it.
  • Log and review tool calls; alert on unusual destinations or volumes.
  • Limit tool permissions, rate-limit users, and cap steps and spend per run.
  • Read Risks, ethics and safe use and the OWASP Top 10 for LLM Applications.

PRICES = {"gpt-4o-mini": (0.15, 0.60)}             # illustrative USD per 1M tokens: input, output

def traced_chat(client, user_id: str, feature: str, **kwargs):
    start = time.time()

    try:
        resp = client.chat.completions.create(**kwargs)
        return resp
    except Exception as e:
        status = type(e).__name__
        raise
    finally:
        u = getattr(resp, "usage", None)
        pin, pout = PRICES.get(kwargs["model"], (0, 0))
        cost = ((u.prompt_tokens * pin + u.completion_tokens * pout) / 1e6) if u else 0

            "latency_ms": int((time.time() - start) * 1000), "status": status,
            "tokens_in": u.prompt_tokens if u else 0, "tokens_out": u.completion_tokens if u else 0,
            "cost_usd": round(cost, 6),

def ask_data(question: str, db):
    sql = ask_llm(f"Schema: {SCHEMA}\nWrite ONE read-only MySQL SELECT that answers: {question}\nReturn only the SQL.").strip().rstrip(";")
    if not re.match(r"(?is)^\s*select\b", sql) or ";" in sql or re.search(r"(?i)\b(insert|update|delete|drop|alter|grant)\b", sql):
        raise ValueError("Unsafe or invalid query blocked")
    rows = db.execute(sql + " LIMIT 200").fetchall()          # db user should have SELECT-only rights

    MCP is an open standard that lets any AI app (host) connect to external tools and data through small servers, so you write an integration once and reuse it across clients.

    Host / Client

    The AI application (IDE, chat app, agent) that talks to MCP servers.

    Server

    Exposes capabilities for GitHub, databases, files, browsers, Slack and more.

    Primitives

    Tools (actions), Resources (data), Prompts (templates).

    3Mini RAG: embeddings + cosine similarity
    import os, numpy as np
from openai import OpenAI

client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])
docs = [
    "Refunds are processed within 5 business days.",
    "Support is available Monday to Friday, 9am to 6pm IST.",
    "Premium plan includes priority support and API access.",
]

def embed(texts):
    r = client.embeddings.create(model="text-embedding-3-small", input=texts)
    return np.array([d.embedding for d in r.data])

doc_vecs = embed(docs)

def answer(question):
    q = embed([question])[0]
    scores = doc_vecs @ q / (np.linalg.norm(doc_vecs, axis=1) * np.linalg.norm(q))
    context = docs[int(scores.argmax())]                      # retrieve
    prompt = f"Answer only from the context.\nContext: {context}\nQuestion: {question}"
    r = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": prompt}],       # generate
    )
    return r.choices[0].message.content

print(answer("How long do refunds take?"))

    Risks, Ethics and Safe Use

    Hallucination

    Plausible but false answers. Verify facts, use citations and RAG.

    Bias and fairness

    Models inherit bias from data. Test across groups, keep humans in key decisions.

    Privacy and data leakage

    Do not paste secrets, customer data or source code into unapproved tools.

    Security attacks

    Prompt injection, jailbreaks, data poisoning, malicious tools. Apply least privilege.

    Copyright and licensing

    Check licences of training data, open models and generated assets.

    Deepfakes and misinformation

    Synthetic media can deceive. Verify sources and use content provenance tools.

    Energy and cost

    Training and serving big models uses large compute. Prefer smaller models when they suffice.

    Job change

    Tasks change faster than whole jobs. Keep learning and use AI as a skill multiplier.

    Over-reliance

    Safe-use checklist
    • Define what the AI is allowed to do and keep a human approval step for irreversible actions.
    • Remove personal and confidential data before sending it to an external model, or use an approved private deployment.
    • Cite sources and verify numbers, laws, medical, legal and financial claims.
    • Test with evals and red-team prompts before launch, and monitor after launch.
    • Be transparent: tell users when they are talking to AI or viewing AI-generated content.
    • Know the rules that apply to you: EU AI Act, GDPR, India's DPDP Act, sector regulations.

    AI Interview Q and A

    Short, speakable answers for revision, from basic to advanced.

    1Basic
    QuestionShort answer
    What is the difference between AI, ML and DL?AI is the broad goal of intelligent machines, ML is AI that learns from data, and DL is ML using deep neural networks.
    What is supervised vs unsupervised learning?Supervised uses labelled data to predict outputs; unsupervised finds structure in unlabelled data.
    What is overfitting and how do you reduce it?The model memorises training data. Use more data, regularisation, dropout, simpler models, early stopping and cross-validation.
    What is a neural network?Layers of connected neurons with weights and activation functions that learn patterns by gradient descent.
    What is generative AI?Models that create new content such as text, images, audio, video and code.
    What is a token?A piece of text (word or sub-word) that an LLM reads and generates; limits and costs are measured in tokens.
    Why is the train / test split needed?To measure performance on data the model has not seen, giving an honest estimate of real-world accuracy.
    What is hallucination?When an LLM produces fluent but incorrect or invented information.
    2Intermediate
    QuestionShort answer
    What is a Transformer?An architecture using self-attention to relate all tokens in a sequence in parallel; the base of modern LLMs.
    What is RAG and why use it?Retrieve relevant documents and add them to the prompt so answers are grounded, current and cite sources, without retraining.
    RAG or fine-tuning?RAG for knowledge that changes or must be cited; fine-tuning for style, format or behaviour. They can be combined.
    What are embeddings?Numeric vectors where similar meanings are close together, enabling semantic search.
    Precision vs recall?Precision is the share of predicted positives that are correct; recall is the share of actual positives that were found.
    What is LoRA?Low-Rank Adaptation trains small adapter matrices instead of all weights, making fine-tuning cheap.
    What does temperature do?It scales randomness in token sampling: low is deterministic, high is more varied.
    What is function calling?The model outputs a structured request to call a tool or API, your code runs it and returns the result.
    3Advanced
    QuestionShort answer
    How do reasoning models differ?They are trained with reinforcement learning to produce long internal reasoning before answering, trading latency and cost for accuracy on hard tasks.
    What is MCP?An open protocol that standardises how AI apps connect to tools, resources and prompts through MCP servers.
    How do you evaluate an LLM application?Build a test set of real cases, score with rules, human review and LLM-as-judge, track regressions, and monitor production feedback.
    How do you defend against prompt injection?Treat external content as untrusted, isolate instructions from data, apply least-privilege tools, validate outputs and require human approval for risky actions.
    What is quantization and its trade-off?Storing weights in lower precision to cut memory and speed up inference, with a small possible accuracy loss.
    How does a Mixture-of-Experts model save compute?A router activates only a few expert sub-networks per token, so active parameters are far fewer than total parameters.
    How would you reduce LLM cost in production?Use smaller models for easy tasks, route by difficulty, cache prompts and results, shorten context, batch requests and cap output tokens.
    What is data drift and how do you handle it?Input data changes over time. Monitor distributions and metrics, and retrain or update the model when performance drops.
    4Scenario
